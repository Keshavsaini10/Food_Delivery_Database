Food delivery,
built as microservices.

A documented backend architecture with independently deployable services, event-driven communication, and a saga-based order workflow.

Explore architectureRead project README

Architecture at a glance

The documented design routes client traffic through Kong and coordinates asynchronous work through RabbitMQ.

Client
→
Kong Gateway
→
NestJS Services
↔
RabbitMQ Events

Orders also call the restaurants service through gRPC for pricing and availability. Each service owns its own MongoDB data.

Service boundaries

Responsibilities described in the architecture document.

Identity

Users

User accounts, addresses and JWT issuing.

Catalog

Restaurants

Restaurants, menu items, stock, pricing and availability.

Workflow

Orders

Order lifecycle, saga state and outbox; coordinates order placement.

Transactions

Payments

Payment processing and idempotency keys.

Fulfilment

Delivery

Drivers and delivery records.

Messaging

Notifications

Consumes events and maintains a notification log.
